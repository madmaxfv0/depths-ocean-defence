# Repository cleanup

What changed when the coursework submission was turned into this repository.

## Choosing the baseline

Three copies of the project existed:

| Copy | State |
|---|---|
| Submitted archive (`CW3_Depths`) | Final. Seven fully documented source files. **Used as the baseline.** |
| `Depths_vectorgame` working folder | Earlier. Same seven classes at roughly half the length, without the later features. |
| `demo_dephs` working folder | Earlier. As above, with different power-up class names. |

Every class in the two working folders exists in the submitted version, so nothing unique was left behind.

## Moved and renamed

| Before | After |
|---|---|
| `CW3_Depths/*.java` | `src/*.java` |
| Figure 1 embedded in the report | `docs/screenshots/title-screen.png` |
| Figure 2 embedded in the report | `docs/screenshots/gameplay-wave-4.png` |

## Left out

| Item | Reason |
|---|---|
| `*.class`, `*.ctxt`, `package.bluej` | Generated by BlueJ. |
| The coursework report PDF | Its title page carries student numbers. Its content is reflected in the README. |
| `README.TXT` | Replaced by `README.md`; it also listed student numbers. |
| `metadata.yml` | Submission-system record containing email addresses and a mark. |
| The coursework brief | Module material, not ours to redistribute. |

Nothing was deleted from the original folders.

## Code changes

None. The sources are byte-for-byte the submitted files.

One difference from the submitted report: it lists "enemy torpedoes persist across wave transitions" as a known issue, but the submitted `Game.startWave` already clears the enemy-shot list, so the README does not repeat it.
